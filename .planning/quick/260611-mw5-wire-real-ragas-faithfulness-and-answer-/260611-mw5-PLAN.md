<objective>
Wire real RAGAS evaluation (faithfulness + answer_relevancy) into the RAG eval
harness so the permanently-NULL `faithfulness` / `answer_relevancy` columns in
`rag_eval_observations` get real Gemini-judged scores keyed to `query_id`.

Today `run_retrieval_eval(..., include_ragas=True)` only *averages* observation
scores that were never produced — the producer is missing. This plan adds the
producer behind a lazy-import seam, wires it into the runner, adds a CLI flag to
trigger a live run, and pins the two new deps. The existing aggregation
(`include_ragas=True` -> `rag.faithfulness.avg` / `rag.answer_relevancy.avg`)
lights up unchanged once observations carry real numbers.

Purpose: Replace placeholder-NULL eval columns with trustworthy, query-mapped
faithfulness and answer-relevancy scores for the compliance demo dashboard.
Output: `src/eval/ragas_quality.py` (producer + scorer seam), runner wiring,
`src/eval/cli.py` (--with-ragas), offline tests, dependency pins.
</objective>

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| eval harness → Gemini judge/embeddings API | Gold query text + RAG answers + retrieval snippets are sent to Gemini for scoring (external API) |
| Gemini API → persistence | Untrusted numeric scores (incl. NaN) returned by the judge cross into SQLite |
| .env secrets → process | GEMINI_API_KEY / Langfuse keys loaded at runtime; must never be persisted or echoed |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-mw5-01 | Information disclosure | rag_eval_observations rows | mitigate | Persist ONLY numeric scores + ids + status; never write questions/contexts/answers/raw judge output (bounded-observation privacy is a locked decision; RAGEvalObservationRow has no text columns and schema tests enforce it). |
| T-mw5-02 | Information disclosure | eval CLI stdout / trace metadata | mitigate | CLI echoes only status/run_id/with_ragas; reuse the existing `_EVALUATION_TRACE_ALLOWED_KEYS` allowlist — no query text, snippets, answers, or secrets in trace metadata. |
| T-mw5-03 | Tampering / Denial of service | NaN/inf or exception from judge | mitigate | Coerce NaN→None in `_score_one` BEFORE insert (avoids _coerce_nullable_float ValueError); wrap each sample in try/except→None so one bad sample cannot sink the batch. |
| T-mw5-04 | Information disclosure | GEMINI_API_KEY / Langfuse keys | mitigate | Keys read via get_settings()/env only; never persisted, never echoed; compliance.db and .env never staged in the commit. |
| T-mw5-05 | Denial of service | Gemini rate limits (17 queries × 2 metrics × multi-call) | accept | gemini-2.5-flash limits are generous; loop is sequential + temperature 0; optional tenacity retry. Low-value bursty demo traffic — accepted. |
</threat_model>
