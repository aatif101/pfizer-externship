# Quick Task 260610-3e5: Summary

## What was done

Refactored four tests across `tests/test_compliance_dashboard.py` and
`tests/test_dashboard_compliance_tab.py` to route SQLite db paths through pytest's
`tmp_path` fixture instead of bare relative paths:

- `test_render_compliance_tab_empty_state_does_not_crash` ("empty-dashboard.db")
- `test_render_compliance_tab_populated_source_detail_is_lazy_and_tolerates_missing_image` ("populated-dashboard.db")
- `test_render_compliance_tab_source_detail_image_lookup_uses_selected_run_row` ("visual-dashboard.db")
- `test_compliance_tab_empty_state_uses_shared_copy` ("empty-dashboard.db")

Assertions that embedded the path (empty-state caption text, `image_calls` tuples) were
updated to use the `db_path` variable. Root cause: `render_compliance_tab` calls
`load_extraction_run_summaries` (unmocked in these tests), which opens
`sqlite3.connect(db_path)` and creates 0-byte files in the pytest working directory.

Also deleted the two stale 0-byte junk files (`empty-dashboard.db`,
`populated-dashboard.db`) left in the repo root by earlier runs. `compliance.db`
(27 MB, real app data) was left untouched.
