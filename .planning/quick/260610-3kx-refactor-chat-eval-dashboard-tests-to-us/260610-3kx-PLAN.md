<objective>
Refactor three dashboard test files to stop passing bare relative SQLite paths ("chat.db", "empty-eval.db") into dashboard render functions, using pytest's `tmp_path` fixture instead.

Purpose: Today these tests mock all DB access so no stray files are created — but if mocking ever changes, sqlite3 will silently create 0-byte .db files in the repo root. This exact failure already happened with the compliance dashboard tests and was fixed in commit f2bf580. This plan applies the same established pattern to the remaining three files.

Output: Three updated test files with tmp_path-derived db paths and updated assertions; full test run green; no stray .db files in repo root.
</objective>
