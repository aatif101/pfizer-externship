Identity rules for this plan:

```text
content_sha256 = SHA-256 over the PDF bytes, streamed in fixed-size chunks
new doc_id      = the complete 64-character lowercase content_sha256
legacy doc_id   = sha256(str(Path(pdf_path).resolve()).encode()).hexdigest()[:16]

Lookup priority:
1. an existing row with documents.content_sha256 == content_sha256
2. otherwise, the exact legacy doc_id row
3. otherwise, a new row whose doc_id == content_sha256

Skippable means ALL are true:
- stored content_sha256 exactly equals the current content_sha256
- status == 'ingested'
- page_count > 0
- COUNT(pages for doc_id) == page_count
```

A legacy row whose `content_sha256 IS NULL` is deliberately not skippable. Reuse its 16-character `doc_id` for one successful re-ingest/backfill so downstream foreign keys remain stable. If a reused legacy row already has a different non-null hash, preserve it and ingest the changed bytes under their 64-character content ID.

Public-boundary rule: `ingest_document(pdf_path, db_path, *, identity: DocumentIdentity | None = None)` always performs conversion and persistence. It may reuse a precomputed identity to avoid hashing twice, but it never silently skips. The folder CLI alone applies `--skip-existing` before invoking `ingest_document`; `--no-skip-existing` always invokes the heavy path. This keeps direct-call behavior explicit and prevents the force flag from becoming ineffective.

Privacy contract: `_INGEST_TRACE_METADATA_KEYS` and `_STORAGE_TRACE_METADATA_KEYS` remain bounded operational allowlists. Never add `content_sha256`, `file_path`, `page_text`, `image_blob`, `docling_json`, exception text, or raw PDF bytes to trace metadata, logs, CLI errors, or test failure dumps. Conversion logs use the basename only; validation/provider failures shown by the CLI contain filename plus exception class/reason code, never `str(exc)` or an absolute path.

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| PDF bytes -> identity resolver | Confidential supplier content is read locally to compute SHA-256 before any heavy processing |
| Identity resolver -> legacy SQLite rows | New content identity must coexist with path-derived IDs without destructive guesses or false skips |
| In-memory document snapshot -> SQLite | Header, pages, BLOBs, hash, and status must cross as one transaction |
| Docling compatibility seam -> optional heavy runtime | Current and older supported 2.x APIs are selected lazily without network work at import time |
| Operational metadata -> Langfuse/logs | Identifiers/counts may leave the process; raw content, paths, blobs, JSON, and hashes may not |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-01-04-01 | Tampering | `--skip-existing` false positive | mitigate | Skip only an exact full content hash whose ingested row has a complete declared page set; pending/error/incomplete/null-hash rows reprocess |
| T-01-04-02 | Tampering | legacy path-ID migration | mitigate | Never infer legacy content or rewrite its PK; reuse and backfill only through a successful atomic ingest; changed bytes receive a new content ID |
| T-01-04-03 | Tampering | multi-step SQLite persistence | mitigate | One connection + explicit transaction + rollback; tests inject mid-page failure for both fresh and replacement writes |
| T-01-04-04 | Tampering | `INSERT OR REPLACE` parent deletion | mitigate | Use `ON CONFLICT DO UPDATE` so parent identity is updated in place and unrelated child rows are not cascade-deleted by replacement semantics |
| T-01-04-05 | Information Disclosure | content hash as document fingerprint | mitigate | Persist only in local SQLite; exclude from trace allowlists, logs, CLI output, exception payloads, and test dumps |
| T-01-04-06 | Information Disclosure | page/raw PDF data in traces | mitigate | Preserve strict metadata allowlists and forbidden-payload tests covering paths, text, images, Docling JSON, hashes, and raw exceptions |
| T-01-04-07 | Repudiation | shifted/duplicated page evidence | mitigate | Exact 0-indexed key lookup only; sparse provenance regression proves missing pages remain empty and cited text is not borrowed |
| T-01-04-08 | Denial of Service | eager/repeated VLM setup | mitigate | Streaming hash reads, offline-safe imports, process-cached converter, and modern preset construction without weight downloads in tests |
| T-01-04-09 | Spoofing | truncated-hash collision | mitigate | New identity uses the complete 256-bit lowercase digest plus a unique partial DB index; 16-character IDs remain legacy-only |
</threat_model>
