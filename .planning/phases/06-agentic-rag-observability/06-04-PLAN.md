## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| process -> Anthropic / Gemini APIs | Evidence text and draft leave the machine for critique (required for the feature) |
| LLM response -> CriticVerdict | Untrusted JSON controls the accept/reject decision |
| document text -> critic prompt | Prompt injection embedded in supplier PDFs |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-06-17 | Tampering | critic prompt (prompt injection via evidence) | mitigate | System prompt treats evidence/question as data; different model family from drafter; accept only verdict=="supported" and faithfulness>=threshold; any doubt abstains |
| T-06-18 | Tampering | CriticVerdict parsing | mitigate | Pydantic Literal verdict + Field(ge=0, le=1) + max_length=5 claims; ValidationError -> CriticValidationError -> abstain |
| T-06-19 | Elevation of privilege | silent fallback to a weaker critic | mitigate | build_critic_provider has no cross-provider fallback; test proves a missing key raises even when GEMINI_API_KEY is set (D-02) |
| T-06-20 | Information disclosure | provider error messages | mitigate | Only `exc.__class__.__name__` crosses the boundary; generation spans capture_input/output=False; usage-only metadata |
| T-06-21 | Denial of service | retries / API cost | mitigate | tenacity stop_after_attempt(2), no waits in tests; generation token usage recorded for cost visibility |
| T-06-22 | Information disclosure | API keys | mitigate | Keys read from Settings only, never logged or traced; `_is_secret_like` filter in tracing helpers |
</threat_model>
